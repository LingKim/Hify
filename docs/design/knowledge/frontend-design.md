# 知识库前端方案设计

## 1. 设计目标

知识库页面不是一个后台资源表，而是用户维护文档知识、观察处理状态、验证检索
效果的工作台。

页面需要回答用户的三个核心问题：

- 我有哪些知识库？
- 当前知识库里的文档是否已经可用？
- 这个知识库能不能正确命中我的问题？

## 2. 页面原型

高保真 HTML 原型：

```text
docs/design/knowledge/prototype.html
```

该原型已确认作为前端实现方向。

## 3. 页面结构

### 3.1 顶部区域

顶部显示：

- 页面标题：知识库。
- 简短说明：上传文档后自动抽取、切片、向量化，并在 Agent 会话中引用。
- 主操作：新建知识库、批量上传。

### 3.2 左侧知识空间

左侧不是 Table，而是知识库卡片列表：

- 搜索框。
- 知识库名称。
- 状态：已启用、草稿、已归档。
- 描述。
- 文档数、切片数、最近更新时间。

点击卡片后，右侧切换当前知识库详情。

### 3.3 右侧知识库详情

右侧顶部显示当前知识库概览：

- 名称。
- 状态。
- 文档数、切片数、最近处理状态。
- 检索健康度。
- 操作：上传文档、检索测试、绑定 Agent、设置。

检索健康度一期可以先用静态指标或简单统计：

- 最近检索测试成功率。
- 文档失败率。
- 可检索文档占比。

### 3.4 文档流

文档列表不采用传统表格，而使用文档流：

- 文件类型图标。
- 文件名。
- 文档处理状态。
- 切片数量。
- 处理进度。
- 失败原因。
- 行内更多操作。

状态需要一眼可读，失败状态必须提供原因。

### 3.5 检索测试

检索测试放在详情区右侧或独立 Tab：

- 输入问题。
- 点击测试。
- 展示命中片段。
- 展示相似度、来源文档、页码或段落位置。

检索测试用于让用户在绑定 Agent 前确认知识库质量。

### 3.6 已绑定 Agent

详情区展示当前知识库绑定的 Agent：

- Agent 名称。
- Top K。
- 相似度阈值。
- 是否启用。

一期可以只展示绑定关系。绑定编辑可以通过 Agent 配置页完成，也可以后续在知识库
页面补充快捷入口。

## 4. 交互状态

必须覆盖：

- 知识库为空。
- 知识库加载中。
- 知识库加载失败。
- 文档为空。
- 文档上传中。
- 文档处理中。
- 文档处理失败。
- 检索测试无命中。
- 检索测试失败。

## 5. 前端实现边界

新增前端 domain：

```text
frontend/src/domain/knowledge/
├── types.ts
├── api.ts
├── service.ts
├── queries.ts
└── components.tsx
```

新增页面：

```text
frontend/src/pages/knowledge/KnowledgePage.tsx
```

注册路由和菜单时，页面名称使用“知识库”。

## 6. 设计约束

- 复用现有 `FrameView`、`FormDialog` 等共享 UI，除非能力明显不足。
- 颜色走主题 token，不在业务组件里硬编码最终颜色。
- 操作按钮优先 icon + tooltip。
- 不要求用户输入数据库 ID。
- Agent 绑定知识库时必须使用选项源，不让用户手填 `knowledgeBaseId`。
- 主页面不采用传统 Table 布局。
