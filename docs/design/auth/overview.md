# 登录与鉴权方案设计

## 1. 背景

Hify 已经具备用户管理、密码哈希、JWT helper 和 `/auth/me`，但缺少真实登录入口和前端登录态闭环，导致用户管理等接口只能依赖测试手工构造 token。登录模块的目标是把现有 `users` 账号表接入真实账密认证，并让所有业务页面和接口都基于登录态访问。

## 2. 范围

本期范围：

- 账密登录，账号支持用户名或邮箱。
- 登录成功签发 JWT access token。
- `/auth/me` 返回当前用户信息。
- 所有业务接口要求登录后访问。
- 普通用户和管理员暂时开放同等功能。
- 前端新增 `/login` 页面、路由守卫、退出登录和 Header 用户信息。

本期不做：

- refresh token、服务端 token 黑名单。
- SSO、LDAP、OAuth、自助注册。
- 自助改密、审计日志。
- 细粒度 RBAC 权限矩阵。

## 3. 核心原则

- `auth` 负责“当前访问者是谁”，`user` 继续负责“账号资源如何维护”。
- 密码只在登录请求中短暂使用，数据库只保存哈希，接口永不返回密码哈希。
- 当前阶段只区分是否登录，不根据 `admin/member` 限制功能入口。
- 会话数据必须按当前登录用户隔离，不再在请求中自动创建或复用临时 `root` 用户。

## 4. 验收标准

- 正确账号密码可以登录并拿到 token。
- 错误账号或密码统一返回“用户名或密码错误”。
- 禁用、软删除用户不能登录或访问需登录接口。
- 未登录访问业务接口返回 401。
- 登录后访问用户、Provider、Agent、知识库、工具、会话相关接口成功。
- 前端未登录访问业务页跳转 `/login`，登录后回到原目标页。
- 退出登录清除 token 并回到登录页。
